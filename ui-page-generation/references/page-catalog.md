## 一之补、02-04 / 02-05 定下来的细则（新页面照抄）

| 项 | 规则 |
|---|---|
| 字段展示 | 一格里 **字段名 15/22/600 黑色在上 → 值 13/20/400 浅灰在下 → 状态胶囊**；不要把"值"做大做黑（用户纠正过两次） |
| 状态胶囊 | 浅底 + 彩字、圆角 6、高 20、左对齐单独一行：绿 `#DCEFE4`/`#3E8A62` = 已识别·已匹配·已计算；琥珀 `#F7EFDC`/`#B08A2E` = 待确认·进行中；红 `#F6E6E6`/`#A8454A` = 异常（未匹配、识别失败） |
| 不要警告三角 | 「请确认」这类状态**不用 ⚠**，用琥珀胶囊即可 |
| 分组标题 | 16/24/600 `#18181B`；02-05 最终只留一个「订单信息」，**不分三大类** |
| 卡片标题 | 不带序号、不带图标（18/28/600） |
| 进度条 | 轨道 `#F0F0F2` 高 6 圆角 3；填充琥珀 `#DABE6E`；百分比数字用 `#B08A2E` |
| 底部操作区 | 用**独立圆角面板**（`#F7F8F9`、圆角 14）承载说明 + 输入框 + 按钮，**不要用一条横线分隔** |
| 让 Agent 改 | 输入框（白底、圆角 10、高 56、占位文字举例）+ 黑色圆形发送按钮（白纸飞机）；**不要用「返回修改」按钮** |

## 一之补二、02-08 / 02-03B 又定下来的细则

| 项 | 规则 |
|---|---|
| 导出 | 只做**一个**「导出 ▾」黑底按钮 → 点开下拉三选 **Excel (.xlsx) / PDF (.pdf) / Word (.docx)**；不要并排三个按钮。下拉另做**变体帧**展示展开态（`02-03B2`），浮层必须画在 root 上，否则会被卡片裁切 |
| 模板卡片 | 知识库里只有**图标 + 模板名**（上下居中），**不写更新日期**；选中态 = 品牌浅底 + 品牌描边 + 品牌字 |
| 上传模板 | 一条虚线圆角条：上传图标 + 提示文字 + 右侧「选择文件」小按钮 |
| 勾选风格 | 全站对勾统一用 `w2Check()`（绿色实心勾），**不要混用「✓」文字符号**；ERP/CRM 连接状态那两组也要用它 |
| 进行中 | 「正在登记 CRM…」= **品牌蓝小圆点 + 深色文字**（不要橙色） |
| 状态胶囊 | 浅底圆角胶囊（高 20、圆角 6）：绿=已完成、琥珀=待人工检查/待确认、蓝=因用户修改、红=异常 |
| 分隔 | 要分区块就用**独立圆角框**（`#F7F8F9`、圆角 12），**不要用横线** |
| 金额联动 | 用户改数量/单价后，**总金额必须自动重算**并在回执里写清（例：5,000 × USD 12.50 = USD 62,500.00） |
| CRM 字段取舍 | 只登记下单时**已产生**的信息；尾款/出货/结单等后续才产生的字段不画（CRM 模板里本来就有对应栏位，Agent 拿到后再更新） |
| 文案 | 用户说「不要订单 2 个字」→ ERP 那行写成「ERP 单号 SO#… 已提交」；英文对应 `ERP record … · Submitted` |

## 二、每页固定结构（照抄，不要自创）

### 共用的一条任务流程（全站唯一，别再拆两套）

侧栏「任务流程」**只有一套定义**，8 步，所有走这条流程的页面共用，**只改高亮位置**：

```
生成 PO  →  上传 PO  →  信息解析  →  信息确认  →  OA 审批  →  创建 ERP 订单  →  ERP 订单审核  →  CRM 登记
```

英文：`Generate PO → Upload PO → Parse info → Confirm info → OA approval → Create ERP order → ERP order review → CRM registration`

| 页面 | 高亮 |
|---|---|
| 02-03B 按模版生成 PO | 第 1 步 生成 PO |
| 02-03 创建订单 | 第 2 步 上传 PO |
| 02-04 PO 信息解析 | 第 3 步 信息解析 |
| 02-05 / 02-05A 信息确认 | 第 4 步 信息确认 |
| 02-08 CRM 登记 | 第 8 步 CRM 登记 |

**三种走法（用户 2026-09-18 明确，已经并入一条流程，不要再拆成"生成流程"和"上传流程"两套 UI）**：

1. 按模板生成 PO 后，**客户在聊天窗口里说"已确认这个 PO，请继续"** → Agent 直接跳到「信息解析」（信息已经有了，不需要再上传）。
2. **客户提供已回签的 PO** → 回到**同一个任务的聊天窗口**上传，说"这是客户回签的 PO" → 继续跑「信息解析」。
3. **客户没确认** → 停在「生成 PO」，继续按用户指令修改（改字段、自动重算金额）。

> 02-03B 顶栏页面名 = **生成 PO**（英文 `Generate PO`）；02-03 顶栏保持 **创建订单**。

1. **外壳三块固定**：最左导航条、顶栏、问候卡 —— 见 `design-system.md`「固定不变的三块」，逐像素照抄。
2. 内容列 **960 @ (344, 88)**；卡片间距 **20**；**最后一张卡底边 ≤ 900**，不够就压中间卡的高度（02-03 就是把拖拽区从 170 压到 124 才收下的）。
3. 卡片统一 `v3Card`（圆角 16 + 双层柔和阴影）。
4. **卡片标题不带序号、不带图标**（用户 2026-09-18 明确否掉「① 上传客户 PO」这种写法）；标题 18/28/600。
5. **主按钮 = 黑底白字**（`#111111`、圆角 8），发送按钮是黑圆 + 白纸飞机。
6. 侧栏两种形态都用**菜单式行**（行高 40、圆角 8、行距 4，当前项 `#EAF1F8` + 品牌色文字）；**不要画序号圆圈、不要画节点连线**（方案 B，用户选定）。
7. 字段清单用**圆角格子**分行摆（`#F7F8F9` 底、圆角 8、高 36、间距 12）；**不要用表格、不要横线**；按语义分组（02-03 是 3 / 5 / 3）。
8. 中文版纯中文、英文版纯英文；两版**共用同一套布局代码**，文案放各页的 LANG 表（如 `W3_LANG.cn` / `W3_LANG.en`）。

## 三、新建一个页面（必须按顺序）

1. 读桌面《产品 Prototype  原型.txt》对应章节（`Select-String` 定位后**只读那一段**）。
2. **先在回复里给用户 ASCII 草图**（顶栏 / 侧栏 / 主区卡片都要有，标出间距），等用户确认后再动代码。
3. 新建 `src/pages/<name>.js`：LANG 表（cn + en）+ 生成函数（复用 `v3Card` / `v3Txt` / `v3FillRail` / `w2Icon` / `v3Sun` 等助手）。
4. `build.mjs` 的 `parts` 里把新页面插到 `main.js` 之前；`main.js` 加两个分支（中文 / 英文）；`ui.html` 加两个按钮。
5. 构建 + 自查（见下）。
6. 同步安装目录（E 盘，需授权）→ 校验哈希 → 告诉用户「关掉插件面板重开，点第 N 个按钮」。
