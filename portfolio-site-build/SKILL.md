# 个人作品集网站构建与更新（portfolio-site-build）

> 流程骨架与布局库改编自 **ESTHER不二 (esthersjw)** 的 `esther-design-system`（CC BY-NC-SA 4.0）。
> 配色、字体、组件皮肤**一律用你自己项目的品牌基因**（`references/brand-dna.md` 只给通用占位骨架）；
> 她的三色蓝黄红、奶白底、大圆角 + 柔和投影卡片皮肤、Fraunces/Caveat 字体**一律不取**。

## 中文速查

- 中文名：个人网站构建与更新
- 英文稳定名：`portfolio-site-build`
- 适合：改这个网站的任意页面 / 板块 / 文案 / 样式，加新页，出预览与验收证据
- 不适合：Figma 原型（`ui-page-generation`）、原型落 DEMO（`demo-build`）、通用 UI mockup

## 定位

本站是**单人自用的个人作品集**：原生 HTML/CSS/JS，无框架、无打包、无后端、无账号、无 CDN 依赖。
产物 = 用户 F5 就能看的页面改动 + 一张预览截图 + 一行证据。**不是**一套组件库，也不是通用建站工具。

工程根：`<项目根>`（下文所有路径都相对它）

| 文件 | 作用 |
| --- | --- |
| `site/index.html` | 首页五屏；样式内联在 `<style>` |
| `site/assets/js/site.js` | 滚动淡入 + 词环 + 经历区交互 |
| `site/assets/img/*` | 你的 logo 与图片（透明底原图） |
| `_preview/` | 验收截图 |
| `docs/品牌基因.md` | **全站视觉与语气的唯一依据**（路径可改，开工前确认） |
| `docs\交接-*.md` | 当前进度与踩坑（**开工前读最近一份**） |

站点结构（本例）：**一页五屏 —— 首屏 / PHILOSOPHY / 作品 / JOURNEY / QUEST LOG**，最后是页脚（只放邮箱）。
深度内容压进作品页，**不单开** Case Study / About / Resume 页。

## 输入与上下文（开工前先收齐）

- **用户原话里给了什么**：改哪一页、哪一块、期望长成什么样。他习惯一轮给 1–3 条细节。
- **自己读的**：`site/` 里对应的文件、最近一份 `docs\交接-*.md`、`docs\个人网站-品牌基因.md`。
- 缺的信息才问，一次问一句；**能从文件确认的不要问用户**。新页面 / 新板块先出 ASCII 草图。

## 6 步工作流

### Step 1 定位需求

- 先确认：**动哪一页、哪一块、改完什么算过**。用户没指到的地方一律不碰。
- 能读文件确认的不要问；真会改变结果的才问，一次问一句。
- **新页面 / 新板块：先给 ASCII 草图**（直接写在回复里），用户点头再动代码。

### Step 2 读规范

1. **必读** `references/brand-dna.md` —— 通用占位骨架：色板 token、字号阶梯、禁忌清单。
2. **再用项目实际值覆盖它**：读项目内的品牌基因文件（默认 `docs/品牌基因.md`；找不到就问用户）。
   **冲突时以项目文件为准**——它是这个站唯一视觉依据。
3. 读最近一份 `docs\交接-*.md`（进度与踩坑）。
3. 布局**从 `references/layouts.md` 白名单里选**，不自己发明布局。

### Step 3 读现状，增量改

- 在既有文件上改（`site/index.html` + `site/assets/js/site.js`）：**不整站重写、不换技术栈、不引框架和打包工具**。
- 样式继续写在页面内联 `<style>`；交互只写进 `site/assets/js/site.js`。
- 改动越小越对：用户说「只改这一点」就只改这一点。

### Step 4 选布局

- **每节布局必须不同**（P0）；相邻两节复用同一栅格视为不合格。
- 已用：首屏 = 不对称双栏 4:8 + sticky 顶栏；第二屏 = 左窄右宽 + 竖环词墙。
- 新页 / 新版块从白名单取一个**没用过**的手法（见 `references/layouts.md` 的手法池）。

### Step 5 量像素 + 出预览

对齐、位置、边距这类需求 = **量像素**（截图 → 逐行扫墨迹边界 → 把差值写进 CSS），不靠眼估。

预览铁律（都是踩过的坑）：

- 基准窗口 **1440×900**；版心 1200、页边 32（`.page` max-width 1264）。
- 预览时**临时关掉 `body::after` 纸纹**（`display:none !important`），否则整屏糊成底色。
- 无头 Edge `--screenshot` 抓「滚动后」的状态会出**空白图**：滚动状态改用 Playwright MCP，
  配本地静态服务（`python -m http.server`）打开 `http://127.0.0.1:PORT/index.html`。
- `file://` URL 用**正斜杠**、不要带 `?query`。
- 用 `Select-String` 定位后只读需要的那一段，别整篇打印大文件。

### Step 6 自检 + 交付

- 跑 `references/checklist.md` 的 **P0（全过才交付）**，P1 尽量满足，P2 记录为 backlog。
- 交付话术：**结论先行 + 一行证据**（关键数字或截图路径），不贴大段代码和长输出。
- 产物落 `site/`、`_preview/`、`tmp_out/`；**不动桌面原件**，临时文件用完删。
- 用户验收方式：他在 Edge 里 F5 逐条给反馈 —— 一轮 1–3 条，改完再给预览。

## 硬约束（违反即返工）

1. 只做**桌面网页版**；用品牌基因里的浅色主背景，不要暗色。
2. 首屏**不放照片**；名字位只放 `{姓名}`。
3. 顶栏 **sticky**（滚到任何页面都在顶部），左边只放你的 logo 原图。
4. 导航固定四项：`关于 · 作品 · 经历 · 联系` + `中文 | EN`；中文版先行。
5. 每个 section 布局不同；**不用**「左侧竖线 + 小圆点」的章节轨（Notion 味）。
6. **禁止任何 HTML 默认样式**：默认 `<blockquote>`、`border-left` 引用块、无样式 `<ul>/<ol>`、默认 `<table>` 都不许直接出现。
7. 不用前端框架、不用打包工具、不引外部 CDN（字体现状见 `references/brand-dna.md` §5，要改成自托管**先问用户**）。
8. 不写客户真名、真实单据、银行信息；demo 数据必须一眼看出是虚构。
9. 不自己加东西（数字条、页脚说明、额外板块、额外页面）。
10. 不在对话里贴大段内容；结论先行，验证证据一行带过。

## Definition of Done（完成标准）

1. 用户指到的**每一点都改到了，范围外一个字没动**。
2. `references/checklist.md` 的 **P0 全过**。
3. 有 **1440×900 预览图**落在 `_preview/`；对齐 / 位置类需求带**像素数字**。
4. 页面在浏览器里打开**无控制台报错**，导航与锚点链接都能到达。
5. 交付话术：**结论先行 + 一行证据**；用户 F5 后看到的和预览一致。
6. 临时文件清掉，项目目录里不留垃圾。
